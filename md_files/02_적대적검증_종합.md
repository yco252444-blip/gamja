# 미생물 처리기 프로젝트 적대적 검증 — 현실성·구현성·실전성 종합

작성: 2026-09-21. 범위: ZIP 코드·CSV·문서 직접 검증 + 재실행. 부품 스펙(§7)·보드·전원(§6) 조사는 별도 에이전트 문서(`검증_부품_속도_신뢰성.md`, `검증_보드_전원_안전.md`)에 저장되며 §6에서 종합.
판정 표기: ✔ 재현·직접 확인 / △ 뒷받침 못 찾음 / ✘ 반증됨.

## 0. 한 줄 결론
**인프라(센서→MQTT→Pi→대시보드→릴레이 안전 게이트)는 쓸 만하지만, "AI가 절전에 기여한다"는 핵심 주장은 현재 데이터로 성립하지 않는다.** 모델은 "지금값 유지"보다 못하고, 절전 실측은 0건이며, 처리기 본체가 없다.

## 1. AI·데이터 (재실행으로 확인) — 최대 약점

| # | 검증 | 결과 |
|---|---|---|
| 1 | 학습 스크립트 재실행 | ✔ 검증 MAE 0.0321℃ 재현 |
| 2 | 샘플의 독립성 | ✔ 245개 샘플이 **연속 구간 2개(187개, 58개)** 에서만 생성. 나머지 207개 구간은 190초 미만이라 사용 불가. 2초 stride라 인접 샘플이 거의 동일 → 실질 독립 표본은 수 개 수준 |
| 3 | 검증셋 성격 | ✔ 49개 전부 한 구간(07-30 09:06~09:08 UTC), **정답이 전부 25.5℃(표준편차 0)** |
| 4 | 같은 조건 기준선 | ✔ "2분 뒤 = 지금값" MAE **0.0000**(검증셋). RF 0.032(원 스크립트)~0.077(시드 변경) → **RF가 기준선보다 나쁨** |
| 5 | 구간 단위 교차검증 | ✔ 한 구간을 빼고 학습해 그 구간 예측: RF MAE 0.44℃/0.30℃ vs 기준선 0.18℃/0.00℃ → **기준선 우세** |
| 6 | 분해능 | ✔ DS18B20 9-bit → 0.5℃ 단위. 정답 값이 25.5·26.0 두 개뿐(학습). 예측 오차 0.03℃는 센서 분해능(0.5℃)의 1/16으로 물리적으로 의미 없음 |
| 7 | 분포 범위 | ✔ 실온 23.5~26℃대. 제어 목표 37℃와 무관 (히터 ON·음식물 데이터 0) |
| 8 | 예측 상한 | ✔ 31℃ 클립 → 37℃ 목표에 닿을 수 없어 "조기 OFF" 분기 죽음 |
| 9 | 시간 규모 | △ 발효 베드의 열 시상수는 수십 분~시간 단위일 가능성이 큼(에이전트 조사 대기). 60초 창→120초 뒤 예측은 이 규모에서 정보량이 거의 없는 과제 |

**결론**: 모델이 배운 것은 없다. "AI 예측 기반 제어"를 내세우려면 (a) 실운전 데이터(37℃대·히터 ON/OFF·투입 이벤트), (b) 다른 날 검증, (c) 규칙 기반 대비 Wh·오버슈트 비교가 필요하다. **그 전까지 발표에서 "AI"의 역할은 "규칙 기반 제어 + 급변 감지"로 낮춰 말하는 것이 정직하고 안전하다.**

## 2. 제어·안전 코드 리뷰 (`ai-sensor-node.ino`, `predict_service.py`) — 예상보다 견고한 부분

| 항목 | 판정 | 내용 |
|---|---|---|
| fail-safe 기본값 | ✔ 좋음 | 부팅 시 릴레이 강제 OFF. 센서 무효/NaN, 과열(≥42℃), MQTT 끊김·재연결 중, 명령 stale(20초), 연속 가열 300초 초과 중 **하나라도 걸리면 OFF**. 명령을 서버 것만 믿지 않고 ESP32가 재검증 |
| OFF의 즉시성 | ✔ | 안전 OFF는 최소 유지시간(10초)과 무관하게 즉시 적용 |
| 최소 유지시간 10초 | △ | 기계식 릴레이 보호에는 짧음(수명 관점은 에이전트 문서 참조) |
| 연속 가열 300초 상한 | ✘ 설계 불일치 | 실온→37℃ 가열은 수 분 이상 걸릴 수 있어 상한에 걸려 강제 사이클링. 상한 근거(데이터·열 모델) 없음 |
| 과열 판정 | △ | 같은 DS18B20 1개에만 의존. 센서가 "정상처럼 잘못된 값"을 주면 감지 불가. **독립 하드웨어 차단(서모스탯/열퓨즈) 없음** |
| 0.1초 Fail-Safe(발표) | ✘ | 실제 상수는 15~20초 단위, 1Hz 루프. 발표 주장과 불일치 |
| 릴레이 ON 극성·실제 부하 | △ | ON 동작 실기 미검증(07-31 문서). 최신 설정 `ENABLE_RELAY_CONTROL=false` |
| MQTT 인증 | ✘ 취약 | mosquitto가 `listener 1883 0.0.0.0` + **익명 접속 허용**(설정 파일 주석에 "TODO"). 같은 LAN의 누구나 `inference` 토픽에 `heater_command:on`을 발행할 수 있음. ESP32 재검증(과열·300초·10초 유지)이 최후 방어선이라 즉각 사고는 아니나, **시연장 공용 Wi-Fi에서는 위험** |
| 서버 의존 | △ | 제어 판정이 Pi에 있어 Pi·Wi-Fi 장애 시 히터가 20초 뒤 OFF → 안전하지만 **제어 기능은 정지**. ESP32가 규칙 제어(히스테리시스)를 로컬로 가지면 훨씬 견고 |
| 데이터 품질 | ✔/△ | DHT11 유효 54%, MQ 원값 미보정. 추론 조건이 dht11·mq137 모두 유효를 요구하므로 **추론 성립 프레임이 적음**(07-31 문서: 35회 중 8회) |

| # | 항목 | 결과 |
|---|---|---|
| 1 | **Pi가 필요한가** | **안전 제어에는 불필요.** ESP32 폴더에 RF 모델(`CoreTempModel.h`)과 `CoreTempRegressionEngine.cpp`가 이미 있고, 13특징 RF+규칙은 ESP32 단독으로 충분. Pi는 대시보드·로그용으로 격하하거나 노트북으로 대체하면 SD카드·전원 리스크 제거 |
| 2 | 다른 보드 | UNO Q·R4 WiFi·Pico 2 W·Jetson은 이 워크로드에 이득 없음(Jetson은 과잉). 국내 가격은 검색 스니펫뿐이라 결제 페이지 재확인 필요 |
| 3 | 현 구조의 구멍 | fail-safe(끊기면 OFF) 방향은 맞음. 부족한 것: ①**하드웨어 워치독**(`esp_task_wdt` 없음) ②**독립 과온 차단** ③**릴레이 융착 감지**(INA219 미통합) ④추론 주기 10초 vs 명령 유효 20초 → **메시지 2번 연속 유실 시 히터 OFF** |
| 4 | MQ 히터 전류 | 각 약 150~180mA(MQ-135 datasheet 33Ω·5V ≈ 152mA, MQ-137은 900mW 이하 표기). 문서의 "수십 mA"는 틀림. **5V 레일 최악 합계 약 960mA → 5V 2A 이상 어댑터** 권고 |
| 5 | MQ 센서 주의 | MQ-137 datasheet: 실리콘 실란트 증기에 감도 영구 저하. 5V AO를 ESP32 ADC에 직결하면 허용 입력(VDD+0.3V) 초과 가능 — 사용 모듈의 분압 여부 미확인 → **부품 모델 필요** |
| 6 | 히터 안전 설계 | 12V DC 실리콘 패드 + MOSFET, 12V 라인에 **퓨즈 + KSD301 서모스탯 + 열퓨즈 직렬**. 이렇게 하면 INA219(26V 한도)로 전력 실측도 가능. 전시장의 전열기구 제한은 다른 전시회 사례만 확인, **GIST 규정 미확인 → 운영사 문의 항목에 추가** |
| 7 | 예측의 한계 | 실온 245샘플, 22~31℃ 클립 vs 목표 37℃ → 조기 OFF 사실상 불가. **DS18B20 9-bit 0.5℃ 단계는 내가 CSV에서 확인**(값이 0.5 단위). 0.3K/분 기울기가 양자화에 묻힘 → 12-bit 전환 필요. 지속·선형 외삽 기준선과 시간순 검증 비교 필요 |
| 8 | 상용품 사양 | 린클 프라임 평균 52W·최대 130W(120V 미국판)만 확인. 히터·모터 W, 운전 온도는 공식 페이지에 없음. 37℃ 목표의 근거 못 찾음 |
| 9 | 시연 신뢰성 | 전용 공유기(2.4GHz 고정), 녹화 영상, **예비 XIAO 2개 이상**(이전에 GPIO5/6가 손상된 보드가 있었음) |
| 10 | 미확인 | DS18B20·DHT11 데이터시트, MQ-138 히터, 국내 실제 가격, XIAO 온보드 레귤레이터 정격 |

### 우선순위 개선안 (비용·효과 순)
1. **하드웨어 안전 3종 추가**(퓨즈+서모스탯+열퓨즈) — 몇 천~만 원, 안전·심사 신뢰도 즉시 상승
2. **DS18B20 12-bit 전환·논블로킹 읽기** — 코드 수 줄, 예측 과제의 전제 조건
3. **제어를 ESP32 로컬로 이동**(히스테리시스+급변 감지), Pi는 로그/대시보드만 — 서버·Wi-Fi 의존 제거
4. **MQ 출력 분압 확인**, **5V 2A 이상 전원**
5. **12V DC 히터 패드+INA219**로 전력 실측 A/B 실험
6. 워치독·MQTT 인증(또는 전용 AP)·전용 공유기


## 7. 부품 속도·신뢰성 종합 (`검증_부품_속도_신뢰성.md` 요약)
※ 원문 PDF 직접 열람 항목과 [2차]·[미확인] 구분은 원 문서 참조. Reddit/X는 조사 못 함.

| 부품/주장 | 검증 결과 | 영향 |
|---|---|---|
| **INA219 "히터 전류"** | 핀 허용 -0.3~26V, 션트 ±320mV → 0.1Ω에서 최대 3.2A(12V면 약 38W, 24V면 약 77W). **DC 저전력 히터에서만 성립. AC 220V 직결은 불가·위험.** AC면 PZEM-004T(0.5%)나 CT | 히터를 12/24V DC로 바꾸면 해결(§6-6) |
| **MQ-138 = "VOC로 혐기성 부패 감지"** | MQ-138 매뉴얼 대상 가스는 톨루엔·아세톤·알코올·수소. **H2S·머캅탄·NH3 아님** → 직접 근거 없음. 대안: MQ-136, 전기화학 ME3-H2S/NH3(T90 30~60초, 수명 2년) | 슬라이드 7의 "VOCs 폭증=혐기성" 분류 논리 붕괴 |
| **MQ 예열** | MQ-137/138 모두 매뉴얼에 "Over 48 hours" 명시(24시간 아님). 코드의 60초 워밍업은 정확도 보장이 아님 | 시연 전 이틀 사전 통전 필요, 현장 20h 내 신규 센서 캘리브레이션 불가 |
| **5V AO → ESP32 ADC** | ESP32-S3 입력 High 최대 3.6V, ADC 11dB 유효 0~2.9V(±50mV). **분압 필수**(사용 모듈 분압 여부는 부품 모델 확인 필요) | 포화·소자 손상 위험 |
| **DHT11** | 영문 데이터시트 샘플 주기 2초 → **1Hz 폴링은 스펙 위반**. 0~50℃, 20~90%RH, 결로·부식성 공기 회피 대상 | 처리기 내부(고습·암모니아)와 충돌. 유효 54%의 원인과 일치 |
| **DS18B20** | 변환 9-bit 93.75ms, 12-bit 750ms. 변환 전에 읽으면 **85.0** 반환(학습 CSV에 85℃ 1행 확인) | 12-bit는 1Hz에 빠듯 → 비동기 읽기 필요 |
| **0.1초 Fail-Safe** | 센서 변환만 0.09초 이상, MQTT 명령은 Wi-Fi 절전 DTIM 주기만큼 지연. **노드 내부 로컬 하드웨어 차단으로만 성립** | 발표 문구 삭제 또는 "하드웨어 서모스탯 차단"으로 바꿔야 함 |
| **Modem-sleep 수치** | Espressif 문서 평균 38~40mA(DFS 없음)라 35mA는 근접. **180mA는 공식 근거 없음.** (180-35)/180=**80.6%로 발표의 75%와 산수 불일치.** ESP-IDF 기본값이 이미 MIN_MODEM이라 "켜서 개선"은 기본값 대비 성립 안 할 수 있음 | 슬라이드 5·9·13 수치 재작성 필요 |
| **절감의 크기** | 절감 0.48W는 히터 100W의 0.48%, 500W의 0.1%. **MQ 두 개 히터(약 1.85W)가 이 절감의 약 3.9배를 소비** | "월 1,500원대 운영비" 서사의 핵심 반박 근거. 절전은 히터 듀티에서만 의미 |
| **릴레이 수명** | 전기 수명 10^5회 → 30초 주기 on/off면 **약 35일 만에 소진**. 부팅 시 순간 ON 글리치 있음. 220V 히터엔 영전압 SSR 권장 | 최소 유지 10초는 너무 짧음(수 분 이상 권고), 부트 글리치 대책 필요 |
| **미확인(11개)** | HLW8012/CSE7766/SSR 원문, KC 면제 세부, ESP32-S3 ADC1/ADC2 핀 구분, MQ 응답시간 수치 등 | 원 문서 §9 |

## 8. 종합 판정 (갱신)
| 축 | 판정 |
|---|---|
| 현실성 | **낮음~중간**: 문제(음식물 처리기 전력·악취)는 실재. 그러나 히터 절감 서사가 데이터·부품 사양으로 뒷받침되지 않음 |
| 구현성(20h) | **중간**: 센서·MQTT·안전 게이트는 있음. 챔버·실운전 데이터·전력 측정·통합이 현장 몫 |
| 실전성(현장 시연) | **낮음→중간(개선 시)**: 히터 12V DC 전환+하드웨어 안전+ESP32 로컬 제어로 크게 개선 가능 |
| 기술 신뢰성 | **낮음**: 모델이 기준선 미달, 센서 선택(MQ-138·DHT11) 부적합, 사양 수치 불일치 다수 |
| 안전 | **중간**: 소프트웨어 fail-safe는 견고, 하드웨어 독립 차단·워치독·MQTT 인증 부재 |

### 발표 문구 정정 목록 (Oink에서 반영)
1. "3개월 실측 75% 절감" → 삭제(실측 0)
2. "180→35mA 75%"/"100~240→15~30mA 80%+" → 실측 후 단일 수치, 산수 정정(80.6%), 기본값 대비 여부 확인
3. "월 1,500원대 운영비 vs 월 5~8만 원" → 비교 대상 정정(칩 vs 히터 포함 기기)
4. "0.1초 Fail-Safe" → "하드웨어 서모스탯 즉시 차단(수 초 이내 등 측정값)"
5. "VOC로 혐기성 감지" → MQ-136/H2S 또는 "가스 추세 경고"로 축소
6. "히터 전류 수집" → DC 히터+INA219 구성 후에만
7. "5개 모드 분류" → 구현 후 또는 삭제
