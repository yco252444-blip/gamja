## 2. 3개 보드 역할 분담 및 핀맵 (Board Triad Role Definition)

> 보유 부품 중 **XIAO ESP32S3 3개**를 각각 기능별로 독립시켜, 단일 MCU 병목과 센서 간섭을 원천 차단합니다.

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│ [보드 1] SENSOR NODE (환경 및 미생물 대사 센싱 전문)                                     │
│ • CM1106S4 (NDIR CO₂ 호흡 센서)  : D6(TX) / D7(RX) [UART]                               │
│ • DS18B20 (심부온도 방수 프로브)   : D2 [OneWire]                                        │
│ • BME280 (챔버 내부 온습도/기압)   : D4(SDA) / D5(SCL) [I2C 0x76]                        │
│ • MQ-137 (암모니아 악취 센서)     : D0 [ADC1, 10k:12k 분압 회로 경유]                    │
│ ➔ 역할: 1Hz 주기로 미생물 환경 데이터를 수집하여 MQTT로 브로드캐스트                        │
├────────────────────────────────────────────────────────────────────────────────────────┤
│ [보드 2] CONTROL & SAFETY NODE (히터 스위칭, 팬, 전력 계측 및 3중 안전 하드웨어)          │
│ • IRLZ44N N-MOSFET (히터 제어)   : D8 [PWM/Digital Out, 100Ω 게이트 & 10kΩ 풀다운]       │
│ • INA219 (24V 히터 전압/전류 실측): D4(SDA) / D5(SCL) [I2C 0x40]                        │
│ • 5V 블로워 팬 (배기/환기)        : D3 [PWM Out, NPN 트랜지스터 스위칭]                  │
│ • 하드웨어 안전 직렬망           : 퓨즈(2A) + KSD301(45℃ 서모스탯) + 열퓨즈(70℃)       │
│ ➔ 역할: 센서 데이터를 수신하여 로컬 자율 제어(추세 예측 조기 OFF) 및 하드웨어 안전 인터록 유지│
├────────────────────────────────────────────────────────────────────────────────────────┤
│ [보드 3] LOCAL UI & DISPLAY NODE (본체 부착형 사용자 인터페이스)                         │
│ • 0.96" I2C OLED 디스플레이       : D4(SDA) / D5(SCL) [I2C 0x3C]                        │
│ • WS2812B NeoPixel RGB LED 링    : D1 [Digital Out, 신호등 상태 표시]                   │
│ • 비상 알림 부저 (선택)          : D2 [PWM]                                             │
│ ➔ 역할: 스마트폰이 없는 노약자도 즉시 알 수 있도록 3색 신호등 + Lottie 캐릭터 표정 표출    │
└────────────────────────────────────────────────────────────────────────────────────────┘
```

## 3. 전력 배분 체계 (Power Distribution Architecture)

### 3-1. 전원 레일 분리 규격
* **레일 A (24V 1A DC 어댑터)**: 캡톤 필름 히터(24V 14W, 약 0.58A) 전용 고전압 레일.
* **레일 B (5V 3A DC 어댑터)**: 3개 보드 및 모든 센서/팬 로직 전원.

### 3-2. 전력 소비 예산 (5V 레일 최악 조건 분석)
| 장치 | 정격 전압 | 피크 전류 | 비고 |
|---|---|---|---|
| **보드 1 (센서 노드)** | 5V | 350mA | ESP32 Wi-Fi 송신 피크 포함 |
| └ MQ-137 히터 코일 | 5V | 180mA | 상시 발열 통전 |
| └ CM1106S4 CO₂ 센서 | 5V | 40mA | NDIR 램프 점등 시 |
| └ DS18B20 + BME280 | 3.3V | 5mA | LDO 경유 |
| **보드 2 (제어 노드)** | 5V | 350mA | ESP32 Wi-Fi 피크 포함 |
| └ 5V 블로워 팬 | 5V | 200mA | 풀 가동 시 |
| └ INA219 | 3.3V | 1mA | LDO 경유 |
| **보드 3 (UI 노드)** | 5V | 350mA | ESP32 Wi-Fi 피크 포함 |
| └ WS2812B RGB LED (4~8구) | 5V | 200mA | 화이트 풀 점등 시 최악 조건 |
| └ 0.96" OLED | 3.3V | 25mA | 화면 전체 점등 시 |
| **5V 레일 최악 합계** | | **약 1,701mA (1.7A)** | **5V 2.5A ~ 3A 어댑터 사용 시 40% 이상 안전 마진 확보** |

### 3-3. 전력 배선도 픽토그램 (Star-Ground & Decoupling)

```
 [ 24V 1A 어댑터 (+) ] ────► [ 2A 퓨즈 ] ────► [ KSD301 ] ────► [ 히터 패드 ] ──► (MOSFET Drain)
 [ 24V 1A 어댑터 (-) ] ─────────────────────────┐
                                                 │ (굵은 선)
 [ 5V 3A 어댑터 (+)  ] ─┬────────────────────────┼──────────────────────────────┐
                        ├─► [ 1000µF 전해 캐패시터 ] (벌크 전원 안정화)            │
                        ├─► 보드 1 5V 핀 ──┬─► MQ-137 VCC                      │
                        │                  └─► CM1106S4 VCC                    │
                        ├─► 보드 2 5V 핀 ───► 5V 블로워 팬 (+)                 │
                        └─► 보드 3 5V 핀 ──┬─► WS2812B VCC                     │
                                           └─► OLED VCC                        │
                                                                               │
 [ 5V 3A 어댑터 (-)  ] ──────────────────────────┴──► ★ 공통 단일 접점 접지 ◄──┘
                                                       (STAR GROUND POINT)
                                                       (노이즈 및 접지 루프 방지)
```

## 4. 로컬 네트워크: STA 모드 MQTT 통신망

3개 보드는 모두 현장 공유기(또는 스마트폰 핫스팟/전용 AP)의 Wi-Fi에 **STA(Station) 모드**로 접속하며, 로컬 혹은 원격 MQTT 브로커와 토픽을 주고받습니다.

```
       [ 보드 1: 센서 ]                [ 보드 2: 제어 ]                [ 보드 3: UI ]
              │                               │                               │
              │  PUB: oink/telemetry/sensors  │                               │
              ├──────────────────────────────►│ (온도/CO₂ 읽고 히터 판단)     │
              │                               ├──────────────────────────────►│ (화면에 센서 수치 갱신)
              │                               │                               │
              │                               │  PUB: oink/telemetry/actuator │
              │                               ├──────────────────────────────►│ (신호등 색상 갱신)
              │                               │                               │
              ▼                               ▼                               ▼
     ┌─────────────────────────────────────────────────────────────────────────────┐
     │                       로컬/클라우드 MQTT 브로커 (Broker)                      │
     │                      (Railway Mosquitto or 로컬 브로커)                       │
     └──────────────────────────────────────┬──────────────────────────────────────┘
```

## 5. 원거리 통신망 구축: Railway + Supabase + Vercel

LTE 환경이나 집, 학교 어디서든 기기의 상태를 실시간 확인하고 이상 시 알림을 받을 수 있는 엔드투엔드 파이프라인입니다.

```
 [ 보드 1, 2, 3 ]
        │  (MQTT over TCP, 1883 포트)
        ▼
 ┌──────────────────────────────────────────────────────────┐
 │ Railway.app                                              │
 │                                                          │
 │  1. Eclipse Mosquitto (경량 MQTT 브로커 컨테이너)          │
 │     - 고정 TCP 도메인 프록시 제공 (예: railway.tcp:12345) │
 │     - 인증 토큰/비밀번호 적용                            │
 │                                                          │
 │  2. Bridge Service (Node.js or Python 데몬)               │
 │     - MQTT 토픽 실시간 구독 (`oink/#`)                    │
 │     - 텔레메트리 데이터 정제                               │
 │     - Supabase REST / GraphQL API로 Upsert 전송          │
 └────────────────────────────┬─────────────────────────────┘
                              │ HTTPS / REST (Service Role Key)
                              ▼
 ┌──────────────────────────────────────────────────────────┐
 │ Supabase Database & Realtime                             │
 │                                                          │
 │  • Table: `oink_live_state` (ID: 1 행만 실시간 Update)    │
 │    - temp, co2, humidity, heater_w, saved_wh, status     │
 │  • Table: `oink_event_logs` (과열, 과용량 투입 등 로그)     │
 │  • Realtime Engine 활성화 (테이블 변경 시 웹소켓 즉시 브로드캐스트)│
 └────────────────────────────┬─────────────────────────────┘
                              │ WebSocket Realtime (Anon Key)
                              ▼
 ┌──────────────────────────────────────────────────────────┐
 │ Vercel 원격 반응형 대시보드 (Next.js / React)            │
 │                                                          │
 │  • 어디서나 웹 브라우저(스마트폰/PC)로 접속 가능           │
 │  • Supabase Realtime을 직접 구독하여 0.1초 만에 화면 갱신 │
 │  • [간편 모드]: 신호등 색상 + 캐릭터 표정 + 한 줄 가이드   │
 │  • [전문가 모드]: 실시간 시계열 그래프, CO₂ 대사량, 전력량│
 └──────────────────────────────────────────────────────────┘
```

## 6. 오프라인 단절 대비 방어 설계 (Fail-Safe Autonomy)

외부 원거리 통신망(Railway/Vercel/인터넷)이 끊기더라도 기기가 다운되거나 미생물이 폐사하지 않도록 완벽한 3중 방어막을 둡니다.

1. **로컬 브로커 폴백 (Local Broker Fallback)**:
   * 공유기가 인터넷 회선과 단절되어도 로컬 LAN 안에서 보드 1, 2, 3끼리 MQTT 메시지를 주고받으며 자율 운전 유지.
2. **보드 2의 독립 하드웨어 타임아웃**:
   * 만약 보드 1(센서 노드)이 고장 나거나 MQTT 메시지가 15초 이상 수신되지 않으면, 보드 2는 즉시 **히터를 강제 OFF**하고 비상 안전 모드로 진입.
3. **보드 3의 네트워크 단절 표시**:
   * Wi-Fi 또는 MQTT 브로커 연결이 끊어지면 WS2812B LED가 **파란색 점멸(Wi-Fi Reconnecting)**로 전환되고, OLED에 "오프라인 로컬 운전 중" 표시.

## 7. 3단계 구현 로드맵

1. **Step 1 (하드웨어 배선 및 전원 분배)**:
   * 5V 3A 레일에 보드 3대 및 센서/UI 병렬 결선, 공통 GND 결선 완료.
2. **Step 2 (STA MQTT 펌웨어 플래싱)**:
   * 보드 1(센서), 보드 2(제어), 보드 3(UI) 각각의 아두이노 스케치 업로드 및 로컬 브로커 연동 테스트.
3. **Step 3 (Railway & Vercel 클라우드 연동)**:
   * Railway에 Mosquitto 배포 ➔ Supabase 테이블 생성 ➔ Vercel 웹 뷰어 배포.
