# Claude Code 에이전트 활용 가이드 (팀원용)

**이 문서는 무엇을 위한 건가**
- 목적: 부경대 메이커톤 바이브코딩 입문서 **Part 7**(스킬·하네스·MCP·멀티에이전트) 개념을, 개념 재설명 없이 **이 프로젝트(미생물 처리기, XIAO ESP32S3 펌웨어, 카메라, 센서, 웹/클라우드 대시보드)에서 그대로 써먹을 수 있게** 정리한 카피-붙여넣기형 실전 가이드.
- 전제: Claude Code는 다룰 줄 안다. `.claude/skills/`, `CLAUDE.md`, `tools.txt`가 이 프로젝트에 이미 있다(아래에서 계속 언급).

각 섹션 제목 옆 별표는 우선순위다 — ★필수(지금 당장 도움 됨), ☆있으면 좋음(여유 있을 때).

## 0. 시작하기 — 이 저장소 받기 ★필수

**전제:** GitHub `gamja1610/Oink`(Private repo)에 팀장이 collaborator로 초대했다. 초대 이메일/알림에서 **Accept invitation**을 먼저 눌러야 한다. 수락 전에 클론하면 "repository not found"가 뜬다 — 서버 주소나 네트워크 문제가 아니라 그냥 권한 문제다.

### 방법 A — GitHub Desktop(화면 클릭으로)
1. [desktop.github.com](https://desktop.github.com/) 설치
2. **Sign in to GitHub.com** → 브라우저에서 로그인 (계정 없으면 여기서 가입)
3. **File → Clone repository** → `gamja1610/Oink` 선택 → 저장할 로컬 폴더 지정 → **Clone**

### 방법 B — 터미널 명령으로
1. Git for Windows 설치 ([git-scm.com](https://git-scm.com/downloads), 최신판은 Git Credential Manager 내장)
2. 아무 폴더에서:
   ```powershell
   git clone https://github.com/gamja1610/Oink.git
   ```
3. 인증 필요 시 Git Credential Manager가 자동으로 브라우저를 띄워 로그인한다. 구버전이라 `Username:`/`Password:` 프롬프트만 뜨면 — Username엔 GitHub 아이디, Password 자리엔 **일반 비밀번호가 아니라 Personal Access Token(PAT)**을 넣어야 한다 (GitHub 비밀번호는 2021년부터 git 인증에 안 먹힘). PAT 발급: GitHub → 프로필 → Settings → Developer settings → Personal access tokens → Tokens (classic) → `repo` 권한 체크 → 생성된 토큰 복사.

### 대안 — GitHub CLI (`gh`)
```powershell
gh auth login
```
GitHub.com → HTTPS → **Login with a web browser** 선택 → 코드 복사해 브라우저에 붙여넣기. 그다음:
```powershell
gh repo clone gamja1610/Oink
```

### 클론 후 확인
받은 폴더 안에 `.claude/skills/`, `CLAUDE.md`, `AGENTinstall/`, `md_files/`가 보이면 정상이다.

### 클론 후 작업 흐름
작업 시작 전 `git pull` → 에이전트에게 시키고 결과 확인 → 끝나면 `git add` → `git commit` → `git push`.

### Claude Code 없는 팀원(2명)
클론 받은 뒤 `AGENTinstall/install.bat`을 실행해 Orca + Antigravity(`agy`) 설치. Orca에서 워크스페이스를 **클론 받은 이 폴더**로 지정해야 한다.

**흔한 실수:** 초대 수락을 안 하고 클론부터 시도. 순서는 항상 수락 → 클론이다.

## 1. 스킬(Skill) 만들기 ★필수

**이럴 때 쓴다:** 같은 부탁을 팀원 여러 명이 매번 처음부터 길게 설명하고 있다면, 그게 스킬로 만들 신호다.

### 이미 있는 것부터 확인
`.claude/skills/`에 강사가 제공한 스킬 4개가 이미 들어 있다: `xiao-esp32s3`, `xiao-webcam-ap`, `xiao-webcam-sta`, `xiao-edgeimpulse-train`. **이건 수정 금지**(CLAUDE.md 규칙). 아두이노 업로드, 시리얼, COM 포트, 카메라 관련 작업은 새로 스킬을 만들기 전에 이 4개 중 해당하는 게 있는지 먼저 확인한다.

`graphify`, `grill-me`, `ponytail`은 외부 도구의 심볼릭 링크다(`tools.txt` 참고). 실제 파일은 `.agents/skills/`에 있고 `npx skills add ...`로 각자 설치해야 한다.

### 새 스킬 판단 기준 (3줄)
1. **같은 설명을 세 번 이상 반복했다** → 스킬로 굳힐 시점.
2. **팀원 여러 명이 똑같은 작업을 한다**(예: 센서 로그 정리, 업로드 후 상태 확인) → 혼자만 편해지는 게 아니라 팀 전체가 이득.
3. 반대로 **한 번 하고 끝날 일**이면 스킬로 만드는 시간이 아깝다. 그냥 그때그때 시켜라.

### 실제 예시: "업로드 후 상태 확인" 스킬
이 프로젝트 CLAUDE.md 규칙에 "업로드 후 시리얼 모니터 열지 말고 HTTP(/log 등)로 상태 확인"이 있다. 이걸 매번 설명하는 대신 스킬로 만들면 이렇게 생긴다.

`.claude/skills/upload-check/SKILL.md`:
```markdown
---
name: upload-check
description: XIAO ESP32S3에 펌웨어 업로드한 뒤 정상 동작 확인할 때 사용. 시리얼 모니터 대신 HTTP로 상태 확인.
---

# 업로드 후 상태 확인

## 규칙
1. 업로드 직후 시리얼 모니터(`arduino-cli monitor`)를 **절대 열지 않는다** (DTR/RTS 리셋 함정, 보드가 리셋 루프에 빠질 수 있음).
2. 대신 보드가 노출하는 HTTP 엔드포인트(예: `/log`, `/status`)로 상태를 확인한다.
3. 엔드포인트가 없으면 사용자에게 먼저 물어본다 — 지어내서 접속 시도하지 않는다.
4. 확인한 값이 이상하면(센서 음수, 타임아웃 등) '미검증'으로 기록하고 넘어간다.

## 절차
1. 업로드 완료 메시지 확인
2. `curl http://<보드IP>/log` (또는 알려진 엔드포인트)로 상태 확인
3. 응답 없으면 3초 대기 후 1회 재시도, 그래도 없으면 사용자에게 보고
```

이렇게 폴더 하나 + `SKILL.md` 한 장 만들어두면, 다음부턴 "방금 업로드한 거 확인해줘"라고만 해도 Claude Code가 알아서 이 규칙대로 움직인다.

**흔한 실수:** description을 "센서 관련 도움" 처럼 막연하게 쓰면 필요할 때 안 켜진다. "언제 쓰는지"를 구체적으로 적어야 한다.

## 2. 검증 게이트 / 훅 ★필수

**이럴 때 쓴다:** 센서 값이 이상한데도 액추에이터가 그냥 돌아가 버리는 사고를 막고 싶을 때. CLAUDE.md에 이미 "센서 실패 시 구동 거부"라는 규칙이 있는데, 이걸 사람이 매번 확인하지 않아도 자동으로 걸리게 만드는 게 검증 게이트다.

### 이 프로젝트에 맞는 예시
- "온도 센서 값이 음수이거나 범위를 벗어나면 릴레이/모터 구동 명령을 실행하지 않는다" — 코드 안에 넣는 검증 로직.
- "부팅 시 액추에이터가 전부 OFF 상태인지 확인 후에만 다음 단계로 진행" — CLAUDE.md 규칙을 코드 검증으로 옮긴 것.
- 핵심은 "정말 맞는 값인가"를 판단하려 하지 말고 **"명백히 틀린 값인가"**만 거르는 것 (Part 7에서 배운 것과 동일). 예: 온도 -999도, 타임아웃 등은 누가 봐도 틀렸다 → 이런 것만 걸러도 충분하다.

### Claude Code 훅 설정 — 여기부터는 미검증, 직접 확인 필요
Claude Code에는 특정 작업(파일 저장, 명령 실행 등) 전후에 자동으로 검사를 거는 **훅(Hooks)** 기능이 있고, 이건 `.claude/settings.json`에서 설정한다. **정확한 문법(어떤 이벤트에 걸 수 있는지, 어떤 형식으로 적는지)은 이 가이드에서 지어내지 않는다** — 실수로 틀린 문법을 알려주면 오히려 시간을 버린다. 다음 중 하나로 확인해라:
- 공식 문서: **claude.com/claude-code** 에서 Hooks 관련 문서 검색
- 이 프로젝트에 있는 `update-config` 스킬을 불러서 "업로드 후 자동으로 상태 확인 훅을 걸고 싶어"라고 그대로 말하면 Claude Code가 정확한 설정을 만들어준다 (스킬 이름을 안다면 `/update-config` 또는 그냥 자연어로 요청)
- 확실하지 않으면 Claude Code 자신에게 "훅 설정 문법을 공식 문서에서 확인해서 알려줘"라고 물어라 (WebFetch/WebSearch로 실제 문서를 찾아온다)

**흔한 실수:** 훅을 만능으로 여기고 "정말 맞는지"까지 검증하려는 것. 검증 게이트는 명백한 실패만 거르면 된다 — 완벽을 노리면 오히려 정상 동작까지 막아버린다.

## 3. MCP — 외부 도구 연결 ☆있으면 좋음

**이럴 때 쓴다:** Claude Code가 GitHub 저장소나 Supabase 데이터베이스 같은 외부 서비스를 직접 조작하게 하고 싶을 때(예: "이 커밋 히스토리 확인해줘", "Supabase 테이블 스키마 보여줘"를 Claude Code가 직접 API로 물어보게).

### 이 프로젝트에서 쓸만한 후보 (2026-09 기준 확인함)
- **GitHub MCP 서버** — GitHub 공식 제공. 저장소·이슈·PR을 Claude Code가 직접 다룰 수 있다.
  설치: `claude mcp add github -e GITHUB_PERSONAL_ACCESS_TOKEN=<토큰> -- docker run -i --rm -e GITHUB_PERSONAL_ACCESS_TOKEN ghcr.io/github/github-mcp-server`
  (Docker 없이 HTTP 방식도 있음: 공식 문서 참고)
  출처: [github/github-mcp-server](https://github.com/github/github-mcp-server), [설치 가이드](https://github.com/github/github-mcp-server/blob/main/docs/installation-guides/install-claude.md)
- **Supabase MCP 서버** — Supabase 공식 제공. 프로젝트/테이블 관리, SQL 쿼리, 로그 확인을 Claude Code가 직접 할 수 있다. Oink 방침(project-skills-layout 메모)에 따르면 원격 확인용 클라우드 DB로 Supabase가 후보로 언급됐으니, 실제로 Supabase를 쓰기로 정해지면 이 MCP가 유용하다.
  출처: [supabase-community/supabase-mcp](https://github.com/supabase-community/supabase-mcp), [Supabase 공식 블로그](https://supabase.com/blog/mcp-server)

**주의:** GitHub 토큰은 꼭 필요한 권한만 준 fine-grained 토큰을 쓰고, `.env`나 `secrets.h`처럼 절대 커밋하지 않는다 (CLAUDE.md 시크릿 규칙 그대로 적용).

### 추가하는 법 — 개념만
1. `claude mcp add <이름> ...` 형태의 명령으로 MCP 서버를 등록한다.
2. 등록 후 Claude Code를 재시작하면 그 서버의 도구를 자연어로 부를 수 있다.
3. 정확한 옵션·인증 방식은 서버마다 다르므로, 위에 링크한 공식 문서 또는 **claude.com/claude-code** 문서를 확인해라.

**미검증:** 이 프로젝트에서 실제로 GitHub/Supabase MCP를 설치·테스트해본 적은 아직 없다. 필요해지면 팀원 한 명이 먼저 시도해보고 결과를 공유하는 걸 권한다.

## 4. 서브에이전트 / 멀티에이전트 ☆있으면 좋음

**이럴 때 쓴다:** 여러 사람이 각자 다른 영역(펌웨어/카메라/대시보드/센서)을 동시에 작업할 때, 또는 한 사람이 코드를 짜는 동안 다른 관점에서 검토를 받고 싶을 때.

### 이 팀에 맞는 구체적 시나리오
- **병렬 개발**: 5명이 각자 센서 모듈 하나씩 맡았다면, 각자의 Claude Code 세션이 사실상 독립된 "에이전트"다. 같은 저장소를 공유하니(팀 git repo), 서로 다른 파일/폴더를 건드리게 역할을 나누면 충돌이 적다.
- **작업 중 교차 검토**: 펌웨어 담당이 "이 업로드 코드 짜줘"라고 시키는 동안, 다른 사람이 별도 세션에서 "방금 짠 이 코드에 안전 규칙(액추에이터 OFF, 센서 실패 시 거부) 빠진 거 없는지 검토해줘"라고 시키면 Part 7의 적대적 검증과 같은 효과를 낸다 — 같은 사람이 짜고 같은 사람이 검사하면 자기 실수를 못 보는 경우가 많다.
- **서브에이전트 호출**: Claude Code 안에서 `Agent` 툴로 특정 작업을 통째로 맡길 수 있다. 예를 들어 "센서 로그 파일들 다 모아서 이상치 있는지 정리해줘" 같은, 지금 하던 작업과 독립적인 조사성 작업이면 자연어로 "이 작업은 서브에이전트한테 맡겨서 병렬로 처리해줘"라고 요청하면 된다. 정확한 호출 이름(예: `general-purpose`)이나 문법은 세션마다 제공되는 목록을 참고하는 게 맞고, 이 문서에서 정확한 명령 문법을 단정하지 않는다 — Claude Code에게 "지금 이 조사를 서브에이전트로 나눠서 처리해줘"라고 자연어로 말하면 알아서 처리한다.

**흔한 실수:** 서로 의존하는 작업(예: 센서 코드가 완성돼야 대시보드가 그 형식에 맞춰짐)을 무리하게 병렬로 시키는 것. Part 7에서 배운 질문을 그대로 적용: "이 작업은 앞 결과가 꼭 필요한가?" — 필요하면 순서대로, 아니면 동시에.

## 요약
| 섹션 | 우선순위 | 이 프로젝트에서 바로 쓸 곳 |
|---|---|---|
| 스킬 | ★필수 | 업로드 후 상태 확인, 센서 로그 정리 같은 반복 작업 |
| 검증 게이트/훅 | ★필수 | 센서 이상값일 때 액추에이터 구동 자동 차단 |
