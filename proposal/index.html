02

문제 정의 (Problem Definition)

🧫 1) 미생물 관리를 온전히 사용자에게 의존

  • 가사 노동 절감을 내세운 제품임에도 불구하고, 미생물 관리를 온전히 사용자에게 맡긴다는 한계가 있습니다.
  • 사용자는 미생물의 상태 변화를 알기 어려워 대응이 늦어지고, 결국 미생물이 사멸하는 위험에 노출됩니다.

⚡ 2) 24시간 돌아가는 히터의 에너지 과소비

  • 내부 온도와 관계없이 미생물의 활성 온도를 유지하기 위해 히터가 24시간 내내 돌아갑니다.
  • 공기 온도나 표면 온도만 측정하는 방식으로는 음식물 내부의 실제 온도를 파악하기 어려워, 필요한 수준 이상으로 히터가 가동될 수 있습니다.
03

솔루션 개요 (Solution Overview)

이러한 문제점을 해결하기 위해 미생물의 상태를 스스로 관리해주는 "AI 기반 자율 미생물 관리 시스템"을 설계하였습니다. 이 시스템을 통해 미생물 음식물 처리기에 대한 사용자 부담을 줄이고 진입장벽을 낮추는 역할을 할 수 있습니다.

🌱 미생물 관리 기능

미생물이 음식물을 분해할 때 방출하는 이산화탄소의 양을 측정하여 분해 활성도를 분석합니다. 측정된 수치가 기준치를 벗어나면 사용자에게 알림을 보내고, 센서값들을 분석하여 최적의 해결방법을 제시합니다. 이로써 사용자가 미생물의 상태 변화를 조기에 파악하고 대응하여, 미생물의 사멸 위험을 줄일 수 있습니다.

🔥 히터 발열 제어 기능

음식물 내부의 온도를 반영하여 히터 작동을 정밀하게 조절합니다. 심부 온도 센서를 활용해 미생물 내부의 온도를 측정하여 보다 정밀한 제어를 가능하게 합니다. 이를 통해 미생물 활동에 적합한 온도를 유지하면서 과도한 가열과 불필요한 전력 소비를 줄입니다.

🫧 왜 CO₂로 미생물 활성도를 알 수 있나

음식물(유기물) + 산소 → CO₂ + 물 + 열 미생물이 음식물을 분해하는 과정은 곧 '호흡'입니다. 분해가 활발할수록 같은 시간에 더 많은 CO₂와 열이 나옵니다.

그래서 CO₂ 발생 속도는 퇴비화 분야에서도 미생물 호흡 활성도를 재는 대표 지표로 쓰입니다. Oink는 CO₂ 농도의 절댓값이 아니라 증가 속도(ppm/분)를 보고, 심부 온도와 가스 센서를 함께 읽어 아래처럼 상태를 구분합니다.

🟢 활발히 분해 중 음식물 투입 뒤 CO₂가 빠르게 오르고, 심부 온도도 스스로 오릅니다. CO₂ 상승 ↑ · 심부 온도 ↑ · 가스 낮음
🟡 활성 저하 먹이가 부족하거나 온도·수분이 맞지 않아 호흡이 줄어든 상태입니다. CO₂ 상승 거의 없음 · 심부 온도 ↓
🔴 부패(혐기화) 의심 산소가 부족해 미생물이 제대로 숨 쉬지 못하고 부패 가스가 생깁니다. CO₂ 정체 · 부패 가스 ↑
✅ 분해 완료 분해할 먹이가 줄어들면 CO₂가 다시 기준선으로 내려옵니다. CO₂ 기준선 복귀 · 히터 대기 전환

※ 상태별 기준값(ppm/분, ℃)은 시제품 실측 데이터로 정합니다. 현재 값은 확정 전입니다.

프로젝트 상세 설명 (Project Details)

본 시스템은 미생물 자율 관리와 히터 정밀 발열 제어를 모바일 앱과 연동하여, 사용자의 관리에 대한 부담을 줄이고 미생물 가전으로의 진입장벽을 획기적으로 낮춥니다.

🛠️ 자체 제어 기능 — 앱은 상태 확인과 알림을 담당할 뿐, 실제 제어는 기기가 스스로 수행합니다. ESP32-S3가 센서값을 직접 판단해 히터 ON/OFF · 절전 모드 전환 · 교반 모터 구동 · 과열/과전류 시 전원 차단까지 자체적으로 제어하므로, 사용자가 조작하지 않아도 미생물에게 최적의 환경이 유지됩니다.

Sensing · On-Device AI · App

2. 소비 전력 확인히터·모터가 지금 실제로 쓰는 전력을 실시간 모니터링 Adafruit_INA219 INA219 센서로 전력값을 읽어오는 라이브러리
→

이를 통해 미생물 활동에 최적화된 온도를 정밀하게 유지하면서 불필요한 히터 가동을 차단하여 기존 대비 소비 전력을 크게 절약할 수 있습니다.

05

통합 제어 알고리즘 (Control Algorithm)

센서 수집 · AI 분석 · 정밀 제어 · 물리 안전 · 앱/클라우드 연동의 4단계 Task가 하나의 피드백 루프로 반복됩니다. 물리 안전 제어는 앱·클라우드 연결 여부와 무관하게 항상 우선 실행됩니다.

① 센서 수집 및 데이터 검증

CO₂ · 악취 가스 · 심부 온도 · 소비전력을 수집하고 필터링·누락·고정값·비정상 범위를 검사한 뒤 JSON으로 생성합니다.

② AI 미생물 분석 및 히터·모터 제어

온디바이스 AI가 분해 활성도와 부패 위험을 판단하고, 목표 온도와 심부 온도를 비교해 자가발열 시 절전 모드로 전환합니다.

③ 물리 안전 상태 점검

과전류·과열 시 즉시 전원 차단, 센서 이상 시 격리 후 추정 제어, 구동부 이상 시 정지·복구, 통신 단절 시 NVS 기반 로컬 자율 제어를 유지하며, 모든 점검 결과를 기록해 로컬 제어에 반영합니다.

④ 앱·클라우드 연동

점검 결과를 1~5분 주기로 서버·웹 대시보드에 전송하고, 캐릭터 상태 반영 및 필요 시 푸시 알림을 보냅니다.

🧠 AI가 실제로 하는 일

AI의 역할은 "지금 미생물이 어떤 상태인가"를 판정하는 것입니다. 센서값 하나만 보면 헷갈리는 상황(예: CO₂가 낮은 게 분해 완료인지, 미생물이 약해진 건지)을 여러 센서의 최근 흐름을 함께 보고 구분합니다.

입력 (최근 30~60분 흐름)

  • CO₂ 증가 속도 (ppm/분)
  • 심부 온도와 변화율 (dT/dt)
  • 부패 가스 농도 추세
  • 히터 ON 비율 · 소비 전력
  • 마지막 투입 후 경과 시간
→

모델 (ESP32-S3 안에서 실행)

  • TensorFlow Lite 초경량 분류 모델
  • 시제품 운전 로그로 학습 (투입·과습·과열 상황 라벨링)
  • 인터넷 없이 기기 안에서 수 밀리초 안에 추론
→

출력 → 동작

  • 활발 → 자가발열 활용, 히터 듀티 낮춤
  • 활성 저하 → 목표 온도 유지 + 알림
  • 부패 의심 → 교반 늘림 + 해결책 알림
  • 분해 완료 → 절전 대기
🛡️ AI가 하지 않는 것 — 과열·과전류 차단 같은 안전 판단은 AI에 맡기지 않습니다. 정해진 규칙과 하드웨어 차단 장치(서모스탯·퓨즈)가 항상 우선하며, AI 판정이 틀려도 위험한 상황으로 이어지지 않게 설계합니다.
📏 AI를 쓰는 이유를 숫자로 확인 — 같은 데이터로 단순 규칙(기준치 비교)과 AI 모델의 상태 판정 정확도를 비교하고, AI가 더 나을 때만 채택합니다.

절전 효과 검증 실험 (Verification Plan)

"전력을 아낀다"는 주장을 추정이 아닌 실측으로 보여주기 위해, 전력 측정 센서(INA219)로 히터가 실제로 쓴 전력을 기록하고 기존 방식과 나란히 비교합니다.

A. 기존 방식 (비교군)

공기 온도 기준으로 설정 온도를 유지하며 히터를 24시간 운전합니다. 시중 제품의 동작 방식을 재현합니다.

B. Oink 제어 (실험군)

심부 온도·CO₂ 기반으로 자가발열 구간과 분해 완료를 감지해 히터를 줄입니다.

🔬 실험 방법

  • 같은 크기의 단열 챔버 2개에 같은 미생물 배양토와 같은 양의 음식물을 넣습니다.
  • 두 챔버 모두 INA219로 히터 전압·전류를 1초마다 읽어 전력을 누적(Wh)합니다.
  • 같은 시간 동안 동시에 운전하고, 투입 시점도 맞춥니다.
  • INA219 값은 별도 전력계(멀티미터)로 교차 확인해 측정 오차를 함께 표기합니다.

📊 비교 지표

  • 누적 히터 전력량 (Wh) — 절전 효과의 핵심 지표
  • 히터 가동률 (%) — 하루 중 히터가 켜져 있던 시간
  • 심부 온도 유지 — 적정 온도 범위를 벗어난 시간
  • 분해 활성도(CO₂) — 전기를 아끼느라 미생물 활동이 떨어지지 않았는지 확인
📈 결과는 앱의 전력 리포트 화면과 대회 현장 대시보드에서 두 챔버의 누적 전력 그래프로 실시간 공개합니다. 실험 예정 · 결과 미측정
